# Ionify 0.1.38 distribution alignment

`@ionify/ionify@0.1.38` and all eight platform packages are published. The package requires Node.js 22.x or 24.x and selects an exact-version optional native dependency for macOS ARM64/x64, Windows ARM64/x64 MSVC, or Linux ARM64/x64 GNU/musl. Keep optional dependencies enabled.

```sh
npm install --save-dev @ionify/ionify@0.1.38
# Or:
pnpm add --save-dev @ionify/ionify@0.1.38
# Scaffold a new app:
npm create ionify@latest
```

`create-ionify` remains 0.1.1 and generates an engine dependency on `latest`. Creator and engine versions are independent.

The checked-in distribution payload is copied from the published artifacts. Native binaries are delivered by the npm platform packages rather than committed to Git. PR #10 preserved the owner-controlled public main README byte for byte. Its subsequent reviewed correction changes only the current-version token in “Before you start” from 0.1.37 to 0.1.38; all other owner bytes, documentation and artwork remain intact. The original cross-platform native fix remains attributed to 0.1.36. The Git README intentionally differs from the immutable npm README; repository verification does not authorize repacking or republishing it.

[Projection manifest](0.1.38-projection.json) lists the reviewed public changes, their hashes and expected consumer behavior. The existing publication allowlist remains unchanged. Public source and Git-only verification metadata are distinguished from npm payload bytes.

Fresh npm and pnpm install/build/dev observations cover macOS ARM64. The release also has separate target-native and consumer proof; those are not labelled as fresh registry observations on every OS. See [issue #6](https://github.com/ionifyjs/ionify/issues/6) for the native distribution and diagnostic acceptance scope.
